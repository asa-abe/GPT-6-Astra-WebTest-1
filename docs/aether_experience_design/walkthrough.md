## 2. 体験の要約

仮称「AETHER」のLPを開くと、日本語コピー、相談と制作例へのCTA、立体構造のポスターが表示される。条件を満たす環境だけ、本文を待たせずに静止画から3Dへ切り替わる。

**Hero → Technology → Work → Process → FAQ → Contact**の順に、同じページで価値・根拠・進め方・不安の解消・相談までつなぐ。冒頭ではCoreが分解・整列して技術説明に対応し、制作例以降は3Dを動かし続けない。

スマートフォンでは長い固定演出を避ける。FAQと制作例の補足はページ内で開き、個人情報の方針もページ内に置く。相談はメールリンクを基本とし、独自フォームや送信APIは設けない。

## 5. 数値の位置づけ

以下は設計時に設定した目標。今回の実測は次節に分けて示し、未測定の実機性能・実利用データ・担当者の更新所要時間まで達成済みとはしない。目標の定義は設計書第7・8章を参照する。

| 対象 | 主な目標 |
| --- | --- |
| 初期表示 | 初期JS 35KiB以下、初期表示の合計転送500KiB以下 |
| 遅延3D | コード追加450KiB以下、モデル・テクスチャ込みの追加1.2MiB以下 |
| LP全体 | 制作例・FAQを開き、ページ末尾まで閲覧した合計転送3MiB以下 |
| 実利用性能 | p75でLCP 2.5秒以下、INP 200ms以下、CLS 0.1以下 |
| 更新 | 支給済み素材の制作例差し替え〜ローカル確認15分以内。原稿・承認・CI待ちは除く |
| 制作期間 | 想定体制と素材準備を前提に18〜22営業日、約4〜5週間 |

初期表示の予算と遅延3Dの追加予算は別に管理する。公開前のラボ値から、公開後の実利用データであるINP等の達成を推定して報告しない。

### 5.3 検証の限界

- axe-coreとキーボード操作を通過したことだけでWCAG適合を断定しない。VoiceOver/NVDA、200%文字拡大、400%ズームの手動確認は残っている。
- persistedのpagehide/pageshowとvisibilitychangeはイベント注入でも確認した。実際のモバイルOSによるbfcache保持・破棄や長時間利用は別途確認が必要。
- コピー処理の成功・権限拒否は、OSの共有クリップボードを書き換えないモックで確認した。実際のメール送信や受信はしていない。
- 自動スクリーンショットと目視確認は実施したが、正式承認済みの視覚差分ベースラインはまだない。
- CIファイルは作成済み。作業フォルダーはGit未初期化であり、GitHub Actions上での実行はしていない。

## 8. 起動・確認方法

プロジェクトのルートで実行する。Node 24系・pnpm 11.5.2が前提。依存は`pnpm-lock.yaml`を使い、`pnpm-workspace.yaml`でesbuildの必要なインストール処理だけを許可している。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

開発表示は`http://127.0.0.1:4321/`。本番相当の静的成果物を確認する場合は、開発サーバーを止めて次を実行する。

```sh
pnpm build
pnpm preview
```

```sh
pnpm lint
pnpm test
pnpm build
pnpm exec playwright install chromium firefox webkit
pnpm test:e2e
```

E2Eは専用のローカル配信を4322番ポートで起動・終了する。`tests/serve.mjs`は検証専用で、本番サーバーとして運用しない。3Dの遅延チャンクに対するViteの「非圧縮500kB超」警告は残るが、初期配信には含めず、別途gzipの450KiB上限をビルドで検証している。

## 9. 内容・素材を更新する

| 更新対象 | 編集する場所 |
| --- | --- |
| 見出し・本文・制作例・FAQ・状態メッセージ | `src/data/landing.ts` |
| 公開URL・受信先・運営者・公開承認 | `.env`または配信側のビルド環境変数 |
| 制作例画像 | `src/assets/`の画像と`landing.ts`のimport・alt |
| 色・余白・文字サイズ・レスポンシブ配置 | `src/styles/global.css` |
| Coreの形・光・材質 | `src/experience/scene.ts` |
| スクロール・選択・ポインター | `src/experience/motion.ts` |
| 品質予算・遅延判定 | `src/experience/quality.ts` |

通常の文言・制作例変更では、3DやCSSを触らない。必須項目・重複ID等は`pnpm build`で明示的に失敗する。画像のimport先が存在しない場合もビルドは成功しない。画像はWebP等のローカル素材を使い、alt・使用権利・コンセプト表記も更新する。

今回の制作例はオリジナルSVGを`src/assets/source/`に保存している。編集後の`pnpm assets`で制作例WebPとOGを再生成する。`core.webp`は実3Dの撮影結果を保持し、このコマンドでは上書きしない。

Coreを変更した場合は、表示を確認してから実3Dからポスターを再生成する。

```sh
# 別ターミナルで pnpm dev を起動した状態で実行
pnpm poster
pnpm assets
pnpm build
```

`pnpm poster`の接続先は既定で4321番ポート。変更した場合は`PREVIEW_URL`で指定する。ポスター、元SVG、生成したWebPとOGはソースと一緒に版管理する。WebPだけを手作業で直してもSVGの再生成では保持されない。

## 10. 公開設定・配信・障害対応

`.env.example`を参考に`.env`を用意する。`.env`はGitの除外対象。以下の値に秘密鍵・APIキーを入れる必要はない。

| 変数 | 意味 |
| --- | --- |
| `SITE_MODE` | 通常は`preview`。本公開は`production` |
| `SITE_URL` | HTTPSの公開ルートURL。予約ドメインやフラグメント・認証情報は不可 |
| `CONTACT_EMAIL` | 実際に受信できるメール。予約ドメイン・不正な形式は不可 |
| `OPERATOR_NAME` | 公開する運営者名 |
| `CONTENT_APPROVED` | 原稿・権利・個人情報の方針を実際に承認した後だけ`true` |
| `PUBLIC_DISABLE_3D` | 障害時の静止画版をビルドする場合は`true` |

本公開には**`pnpm build:production`**を使う。公開先のビルドコマンドもこれに固定し、実際の内容を承認していないのにフラグだけ立てない。通常の`pnpm build`はプレビュー既定のため、空の連絡先を許可して`noindex`と準備中表示を出す。本公開用のコマンドではURL・受信先・運営者・承認がなければ失敗する。形式の検証はメールの実受信やドメイン所有の検証を代替しない。

成功した`dist/`だけを静的ホスティングへ配信する。`dist/_headers`はNetlify・Cloudflare Pages等の対応形式で、CSP、MIME sniffing防止、Referrer/Permissions Policy、HTMLの再確認、ハッシュ付き資産の長期キャッシュを指定する。他の配信先では同等のヘッダーを設定し、実HTTP応答を確認する。`astro preview`はこのファイルを本番同様に適用するサーバーではない。HTTPS強制と確認用配信のアクセス制限は配信側で設定する。

`dist/licenses/`にAstro・Three.js・GeistのライセンスとGSAPの著作権・利用条件への通知を同梱する。削除せずに配信する。今回のコード生成型3D・図版の編集原本はプロジェクト内に保持している。ブランド名の商標調査は別途必要。

運用上の障害時は`PUBLIC_DISABLE_3D=true`で本番用ビルドを実行し、静止画版を再配信できる。即時の遠隔設定変更ではない。復旧・ロールバックは、前回成功したHTMLと資産一式を配信先の機能で戻す。旧HTMLが参照する資産を即時削除せず、本文・OG・アンカー・相談窓口を実URLで再確認する。本番配信先が未決定のため、この切り替え演習は未実施。
